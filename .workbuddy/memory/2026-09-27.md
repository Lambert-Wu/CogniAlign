## 通读 CogniAlign 仓库，梳理启动方式与前置工作

项目定位：论文 CogniAlign（arXiv 2506.01890）官方实现，ADReSSo 数据集上的 AD 检测，
不是可运行的应用，而是一套训练脚本。代码全在 `modules/` 下（README 的目录树是错的）。

启动顺序（须在 `modules/` 目录下执行）：
1. `python preprocess/preprocesswhisper.py` —— Whisper(turbo) 词级转写
2. `python preprocess/preprocessembeddings.py` —— 文本 embedding + 音频特征 + 词级对齐
3. `python main.py --config configs/xxx.yaml` —— 训练（README 把 `--config` 拼成了 `--conig`）

### 关键阻塞点（已确认，非猜测）

1. **数据路径全部写死为 Linux 绝对路径** `/dataset/diagnosis/train/...`：
   `dataset.py`（text/audio/labels csv/splits）、`preprocesswhisper.py`、
   `preprocessembeddings.py` 三处都要改。
2. **ADReSSo 数据集不公开**，需向主办方申请；`splits/val_uids{0..4}.npy` 仓库未提供，
   需靠 `dataset.set_splits()` 自己生成（5 折 KFold, random_state=42）。
3. **`preprocessembeddings.py` 顶部三个变量默认是空串**（`textual_model=''`、`audio_model=''`），
   直接跑会在第 38 行 `model.eval()` 处 NameError，必须先手动赋值。
4. **`preprocessembeddings.py` 三条音频分支都跑不通（变量名不一致的历史遗留 bug）**：
   - egemaps / mel 分支只赋值 `features_audio`，但第 286/317/349 行用的是
     `last_hidden_states_audio` → NameError；
   - wav2vec2 分支反过来：第 181 行用 `features_audio`，但只定义了
     `last_hidden_states_audio` → NameError。
   最小修法：在音频特征算完后统一 `last_hidden_states_audio = features_audio`
   （或全部改名成同一个变量）。
5. **distil 命名不一致**：`preprocessembeddings.py` 的分支判断写的是
   `textual_model == 'distilbert'`，但 `name_mapping_text` 的键是 `'distil'`，
   而 `dataset.py` / `configs/default.yaml` 用的也是 `'distil'`。
   结果：填 'distil' 没模型会崩，填 'distilbert' 能跑但存出的文件名少了 `distil`
   后缀，训练时又找不到。修法：把分支判断改成 `'distil'`。
6. 任一样本“对齐数 ≠ token 数”就 `return -1` **中断整批**，无断点续跑。
7. `main.py` 顶层直接 `wandb.login()`，会弹交互式登录。
8. README 漏依赖：`dotmap`（utils.py 用了 DotMap）、`scikit-learn`、`pandas`、`numpy`；
   仓库无 requirements.txt。
9. qwen/mistral 用的是 7B 模型，本地小显存机器跑不动。

### 特征提取阶段到底做了什么（本次结论）

- 文本侧：转写文本喂 BERT 系模型，取 `last_hidden_state`，pad/truncate 到
  (200, 768)（qwen 3584 / mistral 4096 / stella 1536）。存 `<uid><模型>.pt`。
- 音频侧：切帧（eGeMAPS 每 0.1s 一帧 88 维；wav2vec2/mel 每 0.02s 一帧），
  用 tokenizer 的 `offset_mapping` + `##` 子词合并把 token 还原成词，
  再与 Whisper 的词级时间戳逐个匹配，取该词时间段的帧平均填到对应行；
  第 0 行放整段平均。存 `<uid><文本模型>[_pauses][_音频模型].pt`，形状 (200, F)。
- `preprocesswhisper.py` 会用 `segmentation` 目录里的 csv（`speaker == 'INV'`）
  剔除访谈者的话，还会根据词间隔插入 `,` `.` `...` 生成带停顿版转写。
- Whisper 的每词置信度存在 `probablities` 列，但下游没有任何代码使用它。

### 数据集放置方案（给用户的建议）

建议放项目外（`.gitignore` 里没有排除数据目录，放项目内会被 git 跟踪）：
数据根目录 = `/dataset/diagnosis/` 那部分要替换的位置，内部固定结构：

```
<根>/diagnosis/train/
├── audio/{ad,cn}/<uid>.wav              你提供
├── segmentation/{ad,cn}/<uid>.csv       你提供，列需 speaker(INV/PAR)/begin/end；begin/end 单位是毫秒
├── text/{ad,cn}/                        空目录需先建（脚本写 .pt 和 .csv 进去，不会自动建目录）
├── text_transcriptions.csv              脚本①生成
├── adresso-train-mmse-scores.csv        你提供，需含 adressfname、dx 两列
└── splits/                              np.save 不会自动建目录
```

三个硬约束：
- uid 三处必须一致：`audio/<dx>/<uid>.wav`、`segmentation/<dx>/<uid>.csv`、
  `text/<dx>/<uid>.csv`，且标签表 `adressfname` 也等于该 uid。
- `dx` 取值 `cn` → 标签 0，其它 → 1；且 `dx` 的值被直接当文件夹名用，
  所以 text/ 下的子目录名必须和 dx 取值一字不差。
- `segmentation` 列名写错不报错，只是静默跳过剔除访谈者 → 混入医生的话。

注意 `preprocesswhisper.py` 用字符串 replace('audio','text') 推路径，
如果根目录里再出现 "audio" 字样会被误替换，命名时避开。

## 模型改为「本地有就不重新下载」（新增 modules/hf_models.py）

用户要求：models 已经在本地了，运行代码就不要重新下。

**问题根源**：原代码 15 处 `from_pretrained("bert-base-uncased")` 这种写法，
即使本机 HF 缓存里有，transformers 也会先向 huggingface.co 校验版本。
本机连不上，就慢/刷 warning/报错 —— 模型就在硬盘上却跑不起来。

**新增 `modules/hf_models.py`**，核心是 `resolve(repo_id)`，返回本地路径：
1. 项目 `models/<repo末段>/` 里有完整模型 -> 用它（0 网络请求）
2. HF 本地缓存里已有完整副本 -> 用它（不重复下载）
3. 都没有 -> 下载到 `models/<末段>/`（ignore_patterns 跳过非 PyTorch 权重）
4. `COGNIALIGN_OFFLINE=1` 且都没有 -> 报错，告诉用户模型该放哪

目录命名约定：models 下的目录名 = HF repo id 的最后一段
（`distilbert-base-uncased`、`faster-whisper-small` <- Systran/...）。

**完整性判定用「大小 > 0」**：这台 Windows 上 HF 缓存的 snapshots/ 曾出现
0 字节空壳（建符号链接失败），只判 `os.path.exists` 会被骗过去。
实测 `_from_hf_cache('Systran/faster-whisper-small')` 正确返回 None（拒绝空壳）。

**改动**：
- 新增 `modules/hf_models.py`
- `paths.py`：MODELS_DIR 支持 `COGNIALIGN_MODELS_DIR` 环境变量覆盖
- `preprocessembeddings.py`：15 处 from_pretrained 全改走 `resolve()`

## 音频特征改走 wav2vec2 线（用户指定）

用户说"音频提取特征是走 wav2vec2 那条线的" —— 但**当时代码里其实是 egemaps**
（脚本② 第 30 行 + default.yaml 都是 'egemaps'）。按用户要求改成 wav2vec2。

**改了 3 处**：
1. `preprocessembeddings.py`：`audio_model = 'egemaps'` → `'wav2vec2'`
2. `configs/default.yaml`：`audio_model: 'egemaps'` → `'wav2vec2'`
   （两处必须一起改，否则 read_CSV 会去找不存在的文件）
3. wav2vec2 分支的读音频方式：`torchaudio.load` → `librosa.load`

**文件名/维度变化**（后缀映射两边一致，已核对）：
- 后缀：`<uid>distil_egemaps.pt` → **`<uid>distil_audio.pt`**
  （`name_mapping_audio = {'wav2vec2': 'audio', ...}`）
- 维度：88 → **768**
- 帧率：egemaps 10 Hz（0.1s/帧）→ wav2vec2 **50 Hz（0.02s/帧）**
  `segment_length = 50` 正好对应 wav2vec2 的 320 倍下采样（16k/320 = 50）
- 每个 .pt 大小：约 180KB → 约 1.5MB（235 条约 370MB）

**★ 挖出一个会卡死这条线的问题：`torchaudio.load()` 在本机直接崩**
```
RuntimeError: Failed to create AudioDecoder ... Could not load libtorchcodec.
```
原因：torchaudio 2.11 起默认后端是 **TorchCodec**，而 TorchCodec 需要**外部 FFmpeg 库**。
本机没有 ffmpeg（conda 也装不了）→ 直接失败。
而且 `backend="soundfile"/"ffmpeg"/"sox"` **三种写法全部失败**，
警告明说 `'backend' parameter is not used by TorchCodec`。
eGeMAPS 分支用的是 `librosa.load` 才一直躲过这个坑 —— **换分支前一定要单独测读音频**。
改成 `librosa.load(audio_path, sr=16000, mono=True)`（走 libsndfile，只需 libsndfile1）。
本数据集音频本来就是 16k 单声道（实测抽查 8 个全是）。

**顺手把 torchaudio 从依赖里摘掉**（代码已完全不用它，且它的 wheel 必须和 torch
严格配套，是个安装痛点）：
- `preprocessembeddings.py` 删除 `import torchaudio`
- `requirements.txt` 删除 `torchaudio==2.11.0+cu126`，并在三处注释里说明原因
- `tools/check_env.py` 的 preprocess 依赖列表移除 torchaudio

**hf_models.py 加了三级下载回退**（本机代理对 hf-mirror 的 API 是间歇性 502）：
1. `snapshot_download`（走 api.repo_info）→ 2. `list_repo_files` + 逐个 `hf_hub_download`
（走 api/models/.../tree）→ 3. 按常见文件名清单逐个 `hf_hub_download` 试探（**完全不调 API**）
每级都带重试。原因：`hf_hub_download` 走 `/resolve/` 路径一直通，
而两个 API 端点会间歇 502（同一时刻 curl 能通、Python 不通）。
只写第 1 级的话，本地缺模型就永远下不下来。

## ★★ 换线过程中挖出两个真 bug（都不是我改出来的，是原来就有的）

### bug 1：`torchaudio.load` 在缺 ffmpeg 的机器上必崩
（详见上面"音频特征改走 wav2vec2 线"一节）→ 已改成 `librosa.load`。

### bug 2：音频对齐的"空切片 → NaN"，整条 wav2vec2 线一个样本都产不出来

**现象**：改成 wav2vec2 后跑第一个样本就 `SKIP cn/adrso002: 音频特征里出现 NaN`。

**排查过程（值得复用的方法）**：
1. 先用**随机权重**跑 wav2vec2 前向 → 输出 0 个 NaN
   → 排除"随机权重数值不稳定"，确认是**代码 bug**
2. 把 skip 消息改成打印"哪几行是 NaN" → 得到 `1 行: [224]`
   （224 正好是最后一段）
3. 查时间戳边界：音频 78.019 秒 → 3900 帧；最后一个词 `it` 的
   `end = 78.044` 秒 → `ceil(78.044*50) = 3903`，**超出总帧数**

**根因**（在原代码三处对齐分支里都有）：
```python
if end_segment - start_segment < 3:
    start_segment = max(0, start_segment - 2)              # 只夹了下界
    end_segment   = min(n_frames, end_segment + 2)         # 只夹了上界
audio_features_segment = last_hidden_states_audio[start_segment:end_segment]
```
`start_segment` **没有夹上界**。当 start 落在最后一帧之后（时间戳贴着音频末尾），
保护逻辑把 start 夹回 3900（= n_frames），切片 `[3900:3900]` 仍然是空的，
`mean(dim=0)` 对空张量 → NaN → 整个样本被 skip。

**为什么 eGeMAPS 一直没暴露**：它 10 Hz，超界幅度小，保护逻辑的 ±2 帧
恰好能把它拉回有效范围；wav2vec2 是 50 Hz，超界 2 帧后 start 仍等于 n_frames。
**所以这是"靠低分辨率侥幸通过"的隐藏 bug。**

**修法**：新增 `clip_seg(start, end, n_frames)` 局部函数，三处切片前统一调用：
```python
if start_segment >= n_frames:
    start_segment = max(0, n_frames - 1)
if end_segment <= start_segment:
    end_segment = min(n_frames, start_segment + 1)
```
同时把 NaN 的 skip 消息改成打印行号和帧数（下次好定位）。

**验证（真实模型 + 真实音频，两个极端样本）**：

| 样本 | 词数 | 段数/token | 耗时 | 结果 |
|---|---|---|---|---|
| adrso002 | 170 | 224 + 2 = 226 | 7.9 s | ✅ 无 SKIP，(512,768) |
| adrso276（最极端，485 词） | 485 | 510 + 2 = 512（顶满上限） | 33.2 s | ✅ 无 SKIP，(512,768) |

两个都是**0 次 HTTP 请求**，`read_CSV` 能读回：音频 (512,768) / 文本 (512,768)。

**顺带的好消息：wav2vec2 比 eGeMAPS 快得多**
eGeMAPS 每条 43~62 秒（openSMILE 要逐帧算 780 帧）；
wav2vec2 每条 8~33 秒（一次前向）。235 条估计 **约 1 小时**（原估计约 3 小时）。
