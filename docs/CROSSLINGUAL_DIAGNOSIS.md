# 跨语言诊断：信号到底丢在哪一步（2026-10-03，本机）

> 工具：`cognialign/tools/probe_crosslingual.py`（**只读特征，不训练、不写任何产物**）
> 原始输出：`logs/probe_crosslingual_all.log`（已按修正后的掩码重跑）
> 问题：英文训（235 条）→ 中文测（80 条）一直塌到跟瞎猜差不多，不知道该往哪使劲。

---

## 一句话结论

**不是特征不行，是"搬过去"这一步不行。** 冻结特征在同语种里能撑到 **0.89~0.96**（排序分），
跨语言只剩 **0.60~0.72**，而且这点残余还需要满足一个硬前提：**两边必须用同一个编码器**。
论文那套训练出来的融合头在跨语言上（≈0.5，甚至退化）**还不如一个线性探针**。

---

## 怎么做的（不训练深度模型，只看冻结特征）

把两条流的特征按**有效行做掩码平均池化**（音频去补零行、文本去填充行），
得到每条样本一个向量，然后挂一个**逻辑回归**当探针，量五件事：

1. **内部上限** —— 同样这些特征，在各自语言里 5 折能到多少
2. **中英可分性** —— 一个线性分类器能不能把两种语言的特征分开
3. **零样本跨语言** —— 英文 235 条训、中文 80 条测，并套 4 组**不用任何标签**的对齐
4. **长度混淆检查 + 有效行数分布** —— "说了多少字"本身带多少标签信息
5. **置换对照** —— 打乱源域标签重训，确认那点信号不是泄漏

---

## 关于"512"：文件长度 ≠ 有效长度

- 特征文件**永远是 512 行**（对齐后补到 512），但**真正有内容的行数各不相同**。
- 而且音频和文本都是**按 token 对齐**的（每说一个字/词占一行，停顿也占一行），
  所以"有效行数"≈ **说了多少字**，不是秒数。
- 实测分布（`default.yaml`，文本用 tokenizer 精确算）：

| 语言 | 音频有效行数 | 文本有效 token 数 | 被截到 512 的 |
|---|---|---|---|
| 英文 | min 22 / 中位 **137** / max 511 | min 23 / 中位 **138** / max 512 | 1 条 |
| 中文 | min 102 / 中位 **269** / max 511 | min 103 / 中位 **270** / max 512 | 3 条 |

**没有任何样本被"拉平"** —— 只有 1~3 条顶到上限，长度差异完整保留。
所以 512 这个上限**没有**把大家变得一样长。

## 结果一：特征不是瓶颈

| 配置 | 模态 | 英文内部 5 折 | 中文内部 5 折 |
|---|---|---|---|
| `default`（xlmr + xlsr，✅ 对齐已验证） | text | 0.844 | **0.952** |
| | audio | 0.778 | **0.959** |
| | both | 0.863 | **0.952** |
| `xlmr_wav2vec2`（⚠️ 对齐有问题，见文末） | text | 0.844 | 0.952 |
| | audio | 0.835 | 0.876 |
| | both | 0.889 | 0.911 |
| `legacy_distil_wav2vec2` | text | 0.854 | 0.895 |
| | audio | 0.835 | 0.876 |
| | both | 0.884 | 0.921 |

（AUC = 排序分，0.5 瞎猜、1.0 全对。中文只有 80 条、每折 16 条，单折会跳，看均值。）

**读法**：这些**冻结特征**在中文里能撑到 0.9 上下 —— 特征没问题、标签没问题、流程没问题。

---

## 结果二：最大的断点在"两边用不用同一个编码器"

| 配置 | 训练文本 / 测试文本 | 文本侧跨语言 AUC |
|---|---|---|
| `xlmr_wav2vec2`、`default` | **XLM-R / XLM-R**（同一个） | **0.615** |
| `legacy_distil_wav2vec2` | DistilBERT / bert-base-chinese（**两个不同模型**） | **0.253** |

⚠️ **更正**：本节第一版写的是 **0.349**，那是**我自己工具的 bug** 算出来的（见文末"工具修正"）。
用正确的掩码重算是 **0.253**，95% 区间 `[0.158, 0.350]` —— **整段都在 0.5 以下**，
即"系统性反向"：两个模型根本不在一个空间，排序被无关方向决定。

> **这一条比"用不用多语言模型"更关键**：音频侧用的是纯英文的 `wav2vec2-base-960h`
> （中文没训过），但因为训练和测试用的是同一个编码器，跨语言 AUC 反而有 **0.625**；
> 而多语言的 XLS-R **只有 0.599**。
> **结论：跨语言的前提是"共享同一个冻结编码器"，不是"编码器得多语言"。**

中英可分性（线性分类器区分两种语言特征的 AUC）在三套配置、三个模态下几乎全是 **1.000**
（只有 xlsr 音频 0.997）。这条**不能**单独当作"没有共同信号"的证据：文本本来就是两种语言、
录音条件也不同，分得开是意料之中。真正的证据是置换对照（在 0.5 附近）。

---

## 结果三：跨语言那点信号是真的，但很小

以 `default`（xlmr + xlsr，对齐已验证）为例，**英文 235 条训 → 中文 80 条测**：

| 模态 | 对齐 | AUC | 95% 区间（bootstrap，n=80） |
|---|---|---|---|
| text | none | 0.615 | [0.494, 0.738] |
| text | **zscore** | **0.647** | [0.526, 0.767] |
| text | coral | 0.579 | [0.442, 0.703] |
| audio | none | 0.599 | [0.461, 0.721] |
| audio | zscore | 0.592 | [0.451, 0.715] |
| audio | coral | 0.565 | [0.436, 0.687] |
| both | none | 0.639 | [0.516, 0.759] |
| both | zscore | 0.618 | [0.487, 0.739] |

**置换对照**（打乱英文标签后重训，20 次）：
text 0.491 ± 0.190 ｜ audio 0.525 ± 0.091 ｜ both 0.471 ± 0.149 —— 在 0.5 附近，**不是泄漏**。

**必须说清的两件事**：

1. **所有 95% 区间都跨过 0.5** —— n=80 时，0.6 和"瞎猜"在统计上分不开。
   信号是真的（明显高于置换对照），但**远没到能拿来说事的强度**。
2. **无标签对齐的效果落在噪声里**：换一个配置方向就反了 ——
   `xlmr_wav2vec2` 三个模态全涨，`default` 只有 text 涨、audio/both 反而跌。
   **CORAL（对齐二阶矩）一律更差**（d=768、n=235 时协方差估计太不稳）。

## 结果四：一个必须先解决的混淆项 —— 说话长短

只拿"说了多少字"（有效行数）当分数去排标签：

| 配置 | 语言 | 音频有效行数 AUC | 文本 token 数 AUC |
|---|---|---|---|
| `default` | 英文 | **0.387** | 0.387 |
| | 中文 | **0.634** | 0.634 |
| `legacy` | 英文 | **0.409** | 0.409 |
| | 中文 | **0.655** | 0.655 |

**中英文方向相反**：中文里"说得多 → 健康"，英文里"说得多 → 患病"。
所以英文模型学到的"长度用法"搬到中文**必然是反的**，这一点本身就在拖垮跨语言分数。

把长度从特征里线性剔除后再测（`default`）：

| 模态 | 对齐 | 原始 | 去长度 | 差 |
|---|---|---|---|---|
| text | none | 0.615 | 0.640 | +0.025 |
| audio | none | 0.599 | **0.686** | **+0.087** |
| both | none | 0.639 | **0.719** | **+0.080** |

去掉长度反而**变好**（最多 +0.087）——印证"长度在跨语言时是反向的负担"，
而不是"长度在冒充信号"。**但换一个配置（`xlmr_wav2vec2` 的 audio）又是 −0.02**，
`legacy` 的 text 是 −0.105，所以这个效应本身也只有 ±0.1 量级。

> 不管往哪走，**长度必须作为显式混淆项被报告和控制**（分层评估 / 残差化 / 长度匹配），
> 否则任何跨语言结论都站不住。

---

## 结果五：最扎心的一条 —— 训练出来的头不如线性探针

| | 跨语言中文 AUC |
|---|---|
| 论文那套训练的深度模型（交叉注意力 + 门控 + MLP） | ~0.46 ~ 0.52（见 `cognialign/RESULTS.md`，且常退化成"全判患病"） |
| **一个线性探针，架在同样的冻结特征上** | **0.615 ~ 0.719** |

同样的特征、同样的英文训练数据，**越简单反而越好**。说明那个融合头是在**过拟合英文**，
不是表达力不够。

> ⚠️ **公平性说明（不要在论文里漏掉）**：探针用了**掩码池化**（去掉填充行），
> 而现有深度模型的 `mean(dim=1)` **没去填充**（见 `cognialign/RESULTS.md` 的掩码池化一节）。
> 所以这 0.1 的差距里，有一部分是"池化干不干净"，不能全算在"结构过拟合"头上。
> **要下这个结论，必须先把深度模型也换成掩码池化再比。**

## 工具修正（2026-10-03，本机）

**问题**：第一版"找末尾重复行"的填充检测，**对 BERT 系特征失效**。

- 文本特征存的是 HuggingFace 原样的 `last_hidden_state`（`extract_features.py:227`）。
- **XLM-R / RoBERTa**：填充位置的**位置编码被固定住** → 填充行彼此完全相同 → 检测正常。
- **BERT / DistilBERT / bert-base-chinese**：每个位置一个位置编码 → 填充行**各不相同**
  → 检测不出来，误报成"512 行全是内容"（实测 legacy 那套报 511）。

**修法**：文本有效行数改成**用 tokenizer 从转写精确数 token**（`= min(token 数, max_length)`），
跟取特征时那一步（`padding='max_length'`）完全一致；算不出来才退回结构检测，并在输出里标注用了哪种。

**影响**（已重跑全部三套配置，只有 legacy 的文本列变了）：

| 项 | 旧（错） | 新（对） |
|---|---|---|
| legacy 文本 跨语言 none | 0.349 | **0.253** |
| legacy 文本 跨语言 zscore | 0.326 | 0.148 |
| legacy 文本 跨语言 coral | 0.491 | 0.312 |
| legacy 文本 英文内部 5 折 | 0.848 | 0.854 |
| legacy 文本 中文内部 5 折 | 0.902 | 0.895 |
| `default`/`xlmr_wav2vec2` 全部数字 | — | 基本不变（XLM-R 本来就检测正确） |

**对结论的影响**：结论方向不变，反而更硬（0.253 的区间整段 < 0.5）。
但"0.349"这个数请不要再引用。

## ⚠️ 遗留待确认：`feat_xlmr_wav2vec2` 疑似仍然错位（**本机数据，需在服务器复核**）

`cognialign/RESULTS.md` 里写着这套特征已于 2026-10-02 用 `text=xlmr + audio=wav2vec2` 重提、
`check_alignment.py` 复核 train 235/235、test 80/80 通过。但**本机这份数据不是这样**：

```
python cognialign/tools/check_alignment.py --split train -f configs/default.yaml
    -> ✅ 通过（235 条可判定）
python cognialign/tools/check_alignment.py --split test  -f configs/default.yaml
    -> ✅ 通过（80 条可判定）

python cognialign/tools/check_alignment.py --split train -f configs/xlmr_wav2vec2.yaml
    -> ❌ 有问题（229 条）  cn/adrso002  token=255 -> 期望非零行 254，实际 221
python cognialign/tools/check_alignment.py --split test  -f configs/xlmr_wav2vec2.yaml
    -> ❌ 有问题（80 条）   ad/0002      token=258 -> 期望非零行 257，实际 149
```

两条独立佐证：

1. `feat_xlmr_wav2vec2` 的音频与 `feat_distil` 的音频 **逐字节相同**（MD5 全等：
   train 235/235、test 80/80）—— 也就是**两份文件是同一批**，用它"重提"过的话不该如此。
2. 行数：中文 `feat_xlmr_xlsr` 音频有效行中位 **269**，而 `feat_xlmr_wav2vec2` 只有 **148**；
   同一条录音的 xlmr 文本 token 中位是 **270**。音频远少于文本 → 行对不上号。

**最可能的解释：本机 `data/` 是修复前的旧快照**（cognialign/RESULTS.md 记的是服务器上的操作）。
**需要在服务器上跑一次上面两条命令确认**；若服务器也报 ❌，那么所有用到
`feat_xlmr_wav2vec2` 的跨语言结果（尤其含 "both" 的）都要作废重跑。

**本报告哪些数字不受这条影响**：
- `default`（`feat_xlmr_xlsr`）全部数字 —— 对齐已验证 ✅；
- 所有**单模态**数字（text-only / audio-only 探针不关心两条流之间的行对齐）；
- 受影响的只有该配置的 **both** 列。

## 建议怎么走（按性价比排序）

1. **先确认数据**：在服务器上跑 `check_alignment.py`（两条命令，见上）。
   若 `feat_xlmr_wav2vec2` 确实错位，先重提再谈任何结论。
2. **让深度模型换成掩码池化 + 同一个编码器，重训一次跨语言基线。**
   这是唯一能把"结构过拟合"和"池化脏"分开的单变量实验。
3. **长度作为显式混淆项**：评估时加"长度分层"和"去长度残差"两列，不只报一个总数。
4. **统一口径**：所有跨语言数字都配 bootstrap 区间 + 置换对照 + 多数类基线；
   单跑、accuracy 选点的数字一律不采用。
5. **可以写进论文的正面结论**（都已实测）：
   - 冻结特征在两种语言里都能撑起 0.9 上下，跨语言塌缩**不是特征问题**；
   - 跨语言的硬前提是**训练/测试共享同一个冻结编码器**（0.25 → 0.62），
     而不是"编码器得多语言"（XLS-R 并不比纯英文 wav2vec2 好）；
   - 该语料上"跨语言零样本"的真实强度是 **AUC 0.6~0.72 量级、n=80 下不显著**；
   - 无标签特征对齐（标准化）带来的增益**在噪声内**，CORAL 反而有害。
6. 若还想往"拉高数字"走：方向应是**降低头的容量/加正则**，而不是继续加模块
   （门控已被证明被网络吸收，掩码池化只有 +0.008 量级）。

## 复现

```bash
cd <项目根>
PY="D:/anaconda3/envs/alzheimer/python.exe"          # 本机；服务器换成对应解释器

# 三套编码器对照（本文件所有数字的来源）
$PY cognialign/tools/probe_crosslingual.py -f configs/default.yaml              --boot 1000
$PY cognialign/tools/probe_crosslingual.py -f configs/xlmr_wav2vec2.yaml        --boot 1000
$PY cognialign/tools/probe_crosslingual.py -f configs/legacy_distil_wav2vec2.yaml \
        --test-text-model chinese --boot 1000      # 老配置 test 文本是 bert-base-chinese

# 对齐自检（判定 feat_xlmr_wav2vec2 到底有没有错位）
$PY cognialign/tools/check_alignment.py --split train -f configs/default.yaml
$PY cognialign/tools/check_alignment.py --split test  -f configs/default.yaml
$PY cognialign/tools/check_alignment.py --split train -f configs/xlmr_wav2vec2.yaml
$PY cognialign/tools/check_alignment.py --split test  -f configs/xlmr_wav2vec2.yaml
```

⚠️ `legacy_distil_wav2vec2` 必须显式加 `--test-text-model chinese`：
该配置的 `split_textual_model.test: chinese` **只有 `run_preprocess.sh` 读**，
`train.py` / `evaluate.py` 都不读 —— 但**特征文件是当年按 chinese 提的**，
不传这个参数就会去找不存在的 `0002distil_pauses.pt`。
