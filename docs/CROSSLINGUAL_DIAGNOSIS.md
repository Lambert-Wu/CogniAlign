# 跨语言诊断：信号到底丢在哪一步（2026-10-03，本机）

> 工具：`modules/tools/probe_crosslingual.py`（**只读特征，不训练、不写任何产物**）
> 原始输出：`logs/probe_crosslingual_all.log`
> 问题：英文训（235 条）→ 中文测（80 条）一直塌到跟瞎猜差不多，不知道该往哪使劲。

---

## 一句话结论

**不是特征不行，是"搬过去"这一步不行。** 冻结特征在同语种里能撑到 **0.91~0.96**（排序分），
跨语言只剩 **0.60~0.72**，而且这点残余还需要满足一个硬前提：**两边必须用同一个编码器**。
论文那套训练出来的融合头在跨语言上（≈0.5，甚至退化）**还不如一个线性探针**。

---

## 怎么做的（不训练深度模型，只看冻结特征）

把两条流的特征按**有效行做掩码平均池化**（音频去零行、文本去末尾重复的 `<pad>` 行），
得到每条样本一个向量，然后挂一个**逻辑回归**当探针，量四件事：

1. **内部上限** —— 同样这些特征，在各自语言里 5 折能到多少
2. **中英可分性** —— 一个线性分类器能不能把两种语言的特征分开
3. **零样本跨语言** —— 英文 235 条训、中文 80 条测，并套 4 组**不用任何标签**的对齐
4. **长度混淆检查 + 置换对照** —— 确认那点信号是真信号，不是长度假象/泄漏

---

## 结果一：特征不是瓶颈

| 配置 | 模态 | 英文内部 5 折 | 中文内部 5 折 |
|---|---|---|---|
| `default`（xlmr + xlsr） | text | 0.844 | **0.952** |
| | audio | 0.778 | **0.959** |
| | both | 0.863 | **0.952** |
| `xlmr_wav2vec2` | text | 0.844 | 0.952 |
| | audio | 0.835 | 0.876 |
| | both | 0.889 | 0.911 |
| `legacy_distil_wav2vec2` | text | 0.848 | 0.902 |
| | audio | 0.835 | 0.876 |
| | both | 0.885 | 0.946 |

（AUC = 排序分，0.5 瞎猜、1.0 全对。中文只有 80 条、每折 16 条，单折会跳，看均值。）

**读法**：这些**冻结特征**在中文里能撑到 0.9 以上 —— 特征没问题、标签没问题、流程没问题。
塌掉的原因在"英文学的判断依据搬到中文不成立"。

---

## 结果二：最大的断点在"两边用不用同一个编码器"

| 配置 | 训练文本 / 测试文本 | 文本侧跨语言 AUC |
|---|---|---|
| `xlmr_wav2vec2`、`default` | **XLM-R / XLM-R**（同一个） | **0.615** |
| `legacy_distil_wav2vec2` | DistilBERT / bert-base-chinese（**两个不同模型**） | **0.349** |

0.349 低于 0.5，是"系统性反向"——两个模型根本不在一个空间里，排序被无关的噪声方向决定。

> 这一条比"用不用多语言模型"更关键：**音频侧用的是纯英文的 `wav2vec2-base-960h`（中文没训过），
> 但因为训练和测试用的是同一个编码器，跨语言 AUC 反而有 0.625。**
> 反过来，XLS-R（多语言、128 语种）也没有比它更好（0.599 vs 0.625）。
> **结论：跨语言的前提是"共享同一个冻结编码器"，不是"编码器得多语言"。**

中英可分性（一个线性分类器区分两种语言特征的 AUC）在三套配置、三个模态下**全部 = 1.000**
（只有 xlsr 音频是 0.997）——两边分布完全不重叠。但注意这条**不能**单独当作"没有共同信号"的证据：
文本本来就是两种语言、录音条件也不同，分得开是意料之中。真正的证据是下面置换对照。

---

## 结果三：跨语言那点信号是真的，但很小

以 `default`（xlmr + xlsr）为例，**英文 235 条训 → 中文 80 条测**：

| 模态 | 对齐 | AUC | 95% 区间（bootstrap，n=80） |
|---|---|---|---|
| text | none | 0.615 | [0.494, 0.738] |
| text | **zscore** | **0.648** | [0.527, 0.767] |
| text | coral | 0.579 | [0.442, 0.702] |
| audio | none | 0.599 | [0.461, 0.721] |
| audio | zscore | 0.592 | [0.451, 0.715] |
| both | none | 0.639 | [0.516, 0.759] |
| both | zscore | 0.618 | [0.487, 0.739] |

**置换对照**（把英文标签打乱后重训，20 次）：text 0.491 ± 0.190 ｜ audio 0.525 ± 0.091 ｜ both 0.471 ± 0.149
—— 在 0.5 附近，说明上面的 0.6 **不是泄漏**。

**必须说清的两件事**：

1. **所有 95% 区间都跨过 0.5** —— n=80 时，0.6 和"瞎猜"在统计上分不开。
   信号是真的（明显高于 0.5 附近的置换对照），但**远没到能拿来说事的强度**。
2. **无标签对齐（zscore）的效果落在噪声里**：换一个配置方向就反了 ——
   `xlmr_wav2vec2` 三个模态全涨（+0.03~0.04），`default` 只有 text 涨、audio/both 反而跌。
   **CORAL（对齐二阶矩）一律更差**（0.53~0.62），在 d=768、n=235 时协方差估计太不稳。

---

## 结果四：一个必须先解决的混淆项 —— 说话长短

只拿"说话长短"（有效音频帧数 / 文本 token 数）当分数去排标签：

| 语言 | 音频帧数 AUC | 文本 token 数 AUC |
|---|---|---|
| 英文 | **0.387 ~ 0.409** | 0.387 ~ 0.500 |
| 中文 | **0.634 ~ 0.655** | 0.500 ~ 0.634 |

**中英文方向相反**：中文里"说得多 → 健康"，英文里"说得多 → 患病"。
所以英文模型学到的"长度用法"搬到中文**必然是反的**，这一点本身就在拖垮跨语言分数。

把长度从特征里线性剔除后再测（`default`）：

| 模态 | 对齐 | 原始 | 去长度 | 差 |
|---|---|---|---|---|
| text | none | 0.615 | 0.640 | +0.025 |
| audio | none | 0.599 | **0.686** | **+0.087** |
| both | none | 0.639 | **0.719** | **+0.080** |

去掉长度反而**变好**（最多 +0.087）——印证了"长度在跨语言时是反向的负担"，
而不是"长度在冒充信号"。**但换一个配置（`xlmr_wav2vec2` 的 audio）又是 −0.02**，
所以这个效应本身也只有 ±0.09 量级，仍在噪声范围里。

> 不管往哪个方向走，**长度必须作为显式混淆项被报告和控制**（分层评估 / 残差化 / 长度匹配），
> 否则任何跨语言结论都站不住。

---

## 结果五：最扎心的一条 —— 训练出来的头不如线性探针

| | 跨语言中文 AUC |
|---|---|
| 论文那套训练的深度模型（交叉注意力 + 门控 + MLP） | ~0.46 ~ 0.52（见 `RESULTS.md`，且常退化成"全判患病"） |
| **一个线性探针，架在同样的冻结特征上** | **0.615 ~ 0.719** |

同样的特征、同样的英文训练数据，**越简单反而越好**。说明那个融合头是在**过拟合英文**
（和"训得越久中文越差"的观察一致），不是表达力不够。

> ⚠️ **公平性说明（不要在论文里漏掉）**：探针用了**掩码池化**（去掉填充行），
> 而现有深度模型的 `mean(dim=1)` **没去填充**（见 `RESULTS.md` 的掩码池化一节）。
> 所以这 0.1 的差距里，有一部分是"池化干不干净"，不能全算在"结构过拟合"头上。
> **要下这个结论，必须先把深度模型也换成掩码池化再比。**

---

## 现在建议怎么走（按性价比排序）

1. **把深度模型换成掩码池化 + 同一个编码器，重训一次跨语言基线。**
   这是唯一能把"结构过拟合"和"池化脏"分离开的单变量实验，也决定后面所有结论。
2. **长度作为显式混淆项**：评估时加"长度分层"和"去长度残差"两列，不只报一个总数。
3. **统一口径**：所有跨语言数字都配 bootstrap 区间 + 置换对照 + 多数类基线；
   单跑、accuracy 选点的数字一律不采用（`RESULTS.md` 文末已指出这条）。
4. **可以写进论文的正面结论**（都已实测）：
   - 冻结特征在两种语言里都能撑起 0.9+，跨语言塌缩**不是特征问题**；
   - 跨语言的硬前提是**训练/测试共享同一个冻结编码器**（0.35 → 0.62），
     而不是"编码器得多语言"（XLS-R 并不比纯英文 wav2vec2 好）；
   - 该语料上"跨语言零样本"的真实强度是 **AUC 0.6~0.72 量级、n=80 下不显著**；
   - 无标签特征对齐（标准化）带来的增益**在噪声内**，CORAL 反而有害。
5. 若还想往"拉高数字"走：方向应是**降低头的容量/加正则**（探针已经给的提示），
   而不是继续加模块（门控已被证明被网络吸收，掩码池化只有 +0.008 量级）。

## 复现

```bash
cd <项目根>
PY="D:/anaconda3/envs/alzheimer/python.exe"          # 本机；服务器换成对应解释器

# 三套编码器对照（本文件所有数字的来源）
$PY modules/tools/probe_crosslingual.py -f configs/default.yaml              --boot 1000
$PY modules/tools/probe_crosslingual.py -f configs/xlmr_wav2vec2.yaml        --boot 1000
$PY modules/tools/probe_crosslingual.py -f configs/legacy_distil_wav2vec2.yaml \
        --test-text-model chinese --boot 1000      # 老配置 test 文本是 bert-base-chinese

# 单独看某一块
$PY modules/tools/probe_crosslingual.py -f configs/xlmr_wav2vec2.yaml \
        --modalities both --aligns none,zscore
```

⚠️ `legacy_distil_wav2vec2` 必须显式加 `--test-text-model chinese`：
该配置的 `split_textual_model.test: chinese` **只有 `run_preprocess.sh` 读**，
`train.py` / `evaluate.py` 都不读 —— 但**特征文件是当年按 chinese 提的**，
不传这个参数就会去找不存在的 `0002distil_pauses.pt`。
